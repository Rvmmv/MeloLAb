# Сборка Melo Lab

## Версии

| Компонент | Версия |
| --- | --- |
| Android Gradle Plugin | 8.7.3 |
| Gradle | 8.9 |
| JDK для сборки | 17 или 21 |
| Java исходников / байткода | 17 |
| compileSdk / targetSdk | 35 / 35 |
| Build-Tools | 35.0.0 |
| minSdk | 26 (Android 8.0) |
| applicationId / namespace | `com.rvmmv.melolab` |
| Версия приложения | 1.0 |
| Библиотеки выполнения | Только Android SDK |

У приложения нет разрешений INTERNET, доступа ко всему хранилищу, микрофону и фоновой службе. Звук синтезируется локально и останавливается при уходе приложения в фон. MIDI и резервные копии сохраняются через системный выбор документов. Google открывается отдельным браузером.

## Android Studio

Открой папку `MeloLab`, содержащую `settings.gradle` и `build.gradle`. Не открывай отдельно `app`. Studio создаёт `local.properties` с путём к Android SDK.

Установи через SDK Manager **Android SDK Platform 35**, **SDK Build-Tools 35.0.0** и Platform-Tools. В настройках Gradle выбери дистрибутив из `gradle-wrapper.properties` и **JDK 17 или JDK 21**. Если встроенный JDK Studio другой версии, выбери подходящий установленный JDK.

Первая синхронизация требует интернета на компьютере: нужно загрузить Gradle и плагин сборки Android. После синхронизации собери debug APK через меню Build.

## Командная строка

Нужны JDK 17/21 и Android SDK. Путь SDK укажи через `local.properties` либо `ANDROID_HOME`.

Linux / macOS, из корня проекта:

```sh
chmod +x gradlew
./gradlew assembleDebug
```

Windows:

```bat
gradlew.bat assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`. Если установлен обычный Gradle 8.9, можно использовать `gradle assembleDebug`. Release-подпись личным ключом не настроена; debug APK автоматически подписывается и подходит для своего телефона.

## Загрузчик Gradle в архиве

Включены `gradlew`, `gradlew.bat` и небольшой собственный загрузчик с точкой входа `org.gradle.wrapper.GradleWrapperMain`. Это **не официальный бинарный Gradle wrapper**. Его полный исходник находится в `gradle/wrapper/GradleBootstrap.java`; JAR — `gradle/wrapper/gradle-wrapper.jar`.

Он читает URL дистрибутива из `gradle-wrapper.properties`, загружает официальный ZIP Gradle 8.9 по HTTPS, распаковывает в пользовательский кэш и запускает штатный скрипт Gradle. Поддерживает передачу аргументов и кода завершения, `GRADLE_USER_HOME`, `-g`, `--gradle-user-home` и `systemProp.*` для прокси.

SHA-256 в свойствах не указан: первая загрузка защищена HTTPS. При желании можно добавить самостоятельно проверенное значение `distributionSha256Sum`; загрузчик проверит его перед распаковкой.

Проверить загрузчик без сети:

```sh
./gradlew --wrapper-info
```

Пересобрать его из предоставленного исходника с полным JDK:

```sh
java tools/BuildWrapper.java
```

Заменить на официальный wrapper после установки Gradle 8.9:

```sh
gradle wrapper --gradle-version 8.9 --distribution-type bin
```

GitHub Actions в `.github/workflows/android.yml` собирает debug APK установленным Gradle 8.9 и сохраняет артефакт. Workflow здесь не запускался.

## Частые ошибки

- Java не найдена: выбери JDK 17/21 в Gradle JDK или `JAVA_HOME`.
- `SDK location not found`: открой проект в Studio или укажи `sdk.dir` в `local.properties`.
- SDK / Build-Tools не установлены: добавь Platform 35 и Build-Tools 35.0.0.
- Не скачивается Gradle / плагин: проверь интернет и прокси на компьютере.
- `Permission denied`: выполни `chmod +x gradlew`.

## Проверки без Android SDK

```sh
java tools/CheckJavaSyntax.java
```

Проверка разбирает синтаксис Java 17. Она не разрешает Android API, не собирает APK и не проверяет звук на телефоне. Для неё нужен полный JDK.

Проверки музыкальной логики, JSON-хранилища и реального PCM синтезатора без Android:

```sh
java tools/RunEngineTests.java
java tools/RunStoreTests.java
java tools/RunSynthTests.java
```

Проверки охватывают музыкальные расчёты, настоящий экспорт MIDI, JSON резервных копий и создаваемые звуковые данные. Вывод звука через AudioTrack и поведение телефона проверяются отдельно на устройстве.

**Полная Android-сборка, установка APK и запуск на устройстве в среде подготовки не выполнялись.** Результаты доступных проверок перечислены в [VERIFICATION.md](VERIFICATION.md).

## Проверка на своём телефоне

Следующие действия предназначены для готового APK и не заявлены как выполненные:

- Открыть приложение на Android 8+ и Android 15+; проверить панели, клавиатуру, прокрутку и поворот экрана.
- Выбрать F minor; проверить F, G, G#/Ab, A#/Bb, C, C#/Db, D#/Eb и аккорд F minor из F, G#/Ab, C.
- Изменить темп, тональность, лад, длительность аккордов и обращение; проверить сохранение после закрытия приложения.
- Переместить, добавить и удалить аккорд; проверить прослушивание отдельных нот и последовательности.
- Сгенерировать редкую и плотную мелодию, изменить ноты на сетке, отменить генерацию; убедиться, что изменения сохраняются.
- Переключить партии аккордов, мелодии и баса; проверить отсутствие наложенных проигрывателей при повторном нажатии Play.
- Во время звука открыть другое приложение, браузер или заблокировать экран; проверить остановку звука. Проверить потерю аудиофокуса и подключение наушников.
- Проверить конструктор аккордов, обращения, выбор нот на клавиатуре и возможные варианты распознавания.
- Создать, переименовать, скопировать и удалить проект; убедиться, что выбранный проект восстановился после перезапуска.
- Экспортировать MIDI, импортировать его в FL Studio; проверить темп, четыре дорожки включая conductor, партии и завершение всех нот. Переключатели прослушивания не должны удалять партии экспорта.
- Экспортировать и импортировать резервную копию; проверить подтверждение замены и отклонение неверного файла без потери текущих проектов.
- На вкладке Google изменить вопрос, включить и выключить контекст, явно скопировать и открыть браузер; проверить, что ответ остаётся в Google.

Простые синтезированные тембры нужны для проверки высот и сочетаний. Плагины, сэмплы и звучание будущего трека выбираются в FL Studio. AI Mode открывается через браузер без ключей/API и может быть недоступен для конкретного аккаунта или региона.
